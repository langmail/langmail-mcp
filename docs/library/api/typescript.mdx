## preprocess()

Takes raw RFC 5322 email bytes and returns a structured `ProcessedEmail` object. It handles MIME multipart messages and HTML and plain-text bodies, and decodes each part with its charset.

```ts
function preprocess(raw: Buffer): ProcessedEmail
function preprocessString(raw: string): ProcessedEmail
function preprocessWithOptions(
  raw: Buffer,
  options: PreprocessOptions
): ProcessedEmail
```

`preprocess` is **synchronous** and takes a `Buffer`. Use `preprocessString` if you already have the email as a string. Use `preprocessWithOptions` to override the defaults (see [`PreprocessOptions`](#preprocessoptions)).

### ProcessedEmail

Optional fields are declared with `?:` in the generated `.d.ts`, so their type is `T | undefined`, not `T | null`.

| Field | Type | Description |
| --- | --- | --- |
| body | string | Cleaned body text, with quotes and signature removed |
| subject | string \| undefined | Subject line |
| from | Address \| undefined | Sender |
| to | Address[] | To recipients |
| cc | Address[] | Cc recipients |
| date | string \| undefined | ISO 8601 date string |
| rfcMessageId | string \| undefined | `Message-ID` header value |
| inReplyTo | string[] \| undefined | `In-Reply-To` header values (for threading) |
| references | string[] \| undefined | `References` header values (for threading) |
| signature | string \| undefined | Extracted signature, if found |
| rawBodyLength | number | Length of the original body before cleaning |
| cleanBodyLength | number | Length of the cleaned body |
| primaryCta | CallToAction \| undefined | Primary call-to-action link extracted from the HTML body |
| threadMessages | ThreadMessage[] | Quoted reply messages, oldest first |
| isNewsletter | boolean | `true` if the email was identified as a newsletter or bulk marketing message (from the headers; platform notifications are excluded). Always `false` from `preprocessGmail` |

`Address` is `{ name?: string, email: string }`. `CallToAction` is `{ url: string, text: string, confidence: number }`. `ThreadMessage` is `{ sender: string, timestamp?: string, body: string }`.

### PreprocessOptions

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| stripQuotes | boolean | `true` | Remove quoted reply chains |
| stripSignature | boolean | `true` | Remove the trailing signature block |
| maxBodyLength | number | `0` | Truncate the body after N characters. `0` means no limit |

## preprocessGmail()

Adapter for the Gmail API. Takes the response of `gmail.users.messages.get({ id, format: "full" })` from `googleapis` and returns the same `ProcessedEmail` shape as `preprocess()`. It skips MIME parsing, because the Gmail API has already split the message into parts. The decoding and cleaning run in Rust, and the output is byte-identical to the Python and Rust Gmail adapters for the same message. `isNewsletter` is always `false` on this path, because newsletter detection needs the raw headers.

```ts
function preprocessGmail(
  msg: GmailInput,
  options?: PreprocessOptions
): ProcessedEmail
```

`GmailInput` is either the bare `Schema$Message` or the full googleapis response (`{ data: Schema$Message, ... }`). The message must have been fetched with `format: "full"`, so that `payload` is present with headers and base64url-encoded body parts.

**Body selection:** walks `payload.parts` depth-first and picks the first non-attachment leaf of each type. When both `text/html` and `text/plain` are present, HTML wins. Parts with `Content-Disposition: attachment` or a `filename` are skipped.

**Throws:**

- `TypeError` if the input is not an object.
- `Error` if the message has no `payload` (it wasn't fetched with `format: "full"`).
- `Error` if the chosen body part is stored as an attachment: Gmail returned `body.attachmentId` instead of `body.data` because the body was too large to inline. Fetch it with `users.messages.attachments.get` and inline the decoded content.

<Note>
  langmail does not bundle or depend on `googleapis`: it only reads the shape of the response. Bodies are decoded as UTF-8 and the `charset` parameter of each part is not read, so legacy 8-bit encodings may come out garbled.
</Note>

## toLlmContext()

Takes a `ProcessedEmail` and returns a deterministic plain-text string to put straight into a prompt. The output has a header block (FROM, TO, SUBJECT, DATE) followed by a `CONTENT:` section.

```ts
function toLlmContext(email: ProcessedEmail): string
function toLlmContextWithOptions(
  email: ProcessedEmail,
  options: LlmContextOptions
): string
```

Use `toLlmContextWithOptions` to control the rendering, for example to include the quoted reply history.

### LlmContextOptions

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| renderMode | `RenderMode.LatestOnly` \| `RenderMode.ThreadHistory` | `LatestOnly` | `LatestOnly` leaves quoted content out; `ThreadHistory` adds the quoted replies below the main content as a chronological transcript |

<Warning>
  Quote detection is heuristic. [Concepts, Caveats](/library/concepts#caveats) says where its accuracy drops.
</Warning>
