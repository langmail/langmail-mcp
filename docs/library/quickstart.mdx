## TypeScript / Node.js

Call `preprocessString()` with a raw email string, then pass the result to `toLlmContext()` to get a clean context block for your prompt. If you already have the email as a `Buffer`, use `preprocess()` instead.

```ts
import { preprocessString, toLlmContext } from "langmail"
import { readFileSync } from "fs"

// load a raw .eml file as a string
const raw = readFileSync("email.eml", "utf8")

// parse and clean (synchronous)
const parsed = preprocessString(raw)

// render as context for a prompt
const context = toLlmContext(parsed)

console.log(context)
```

### Example output

For a typical email in a reply chain, the output looks like this:

```text
FROM: Alice <alice@example.com>
TO: Bob <bob@example.com>
SUBJECT: Q4 budget review
DATE: 2024-11-12T09:30:00Z
CONTENT:
Hi,

Following up on the Q4 numbers. Can you send
the updated forecast by Friday?
```

### Gmail API

If your app already calls `gmail.users.messages.get({ format: "full" })` through `googleapis`, pass the response to `preprocessGmail` instead of switching to `format: "raw"`:

```ts
import { preprocessGmail, toLlmContext } from "langmail"
import { google } from "googleapis"

const gmail = google.gmail({ version: "v1", auth })
const { data: msg } = await gmail.users.messages.get({
  userId: "me",
  id: messageId,
  format: "full",
})

const parsed  = preprocessGmail(msg)
const context = toLlmContext(parsed)
```

`preprocessGmail` walks `payload.parts`, base64url-decodes the HTML or text body, normalizes the headers and runs the same cleaning pipeline as `preprocess`, with no MIME re-parsing and no extra fetch. On this path `isNewsletter` is always `false`, because newsletter detection needs the raw headers.

<Note>
  langmail does not bundle or depend on `googleapis`: it only reads the shape of the response. Install `googleapis`, or any client that returns the same `Schema$Message`, yourself.
</Note>

## Python

`preprocess()` takes raw bytes, so open the file in binary mode (`"rb"`).

```python
from langmail import preprocess, to_llm_context

with open("email.eml", "rb") as f:
    raw = f.read()

parsed  = preprocess(raw)
context = to_llm_context(parsed)

print(context)
```

### Gmail API

If you call the Gmail API with `format='full'`, serialize the response with `json.dumps` and pass it to `preprocess_gmail`. You don't need to fetch the raw MIME again:

```python
import json
from googleapiclient.discovery import build
from langmail import preprocess_gmail, to_llm_context

gmail = build("gmail", "v1", credentials=creds)
msg = gmail.users().messages().get(
    userId="me", id=message_id, format="full"
).execute()

parsed  = preprocess_gmail(json.dumps(msg))
context = to_llm_context(parsed)
```

`preprocess_gmail` walks `payload.parts`, base64url-decodes the HTML or text body and runs the same cleaning pipeline as `preprocess`.

## Rust

`preprocess` returns a `Result<ProcessedEmail, LangmailError>`, and `to_llm_context` is a method on `ProcessedEmail`.

```rust
use langmail::preprocess;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let raw = std::fs::read("email.eml")?;
    let parsed  = preprocess(&raw)?;
    let context = parsed.to_llm_context();

    println!("{}", context);
    Ok(())
}
```

### Gmail API

For a message from the Gmail API, serialize the response with `serde_json` and pass it to `langmail::adapters::preprocess_gmail`. You don't need to fetch the raw MIME again:

```rust
use langmail::adapters::preprocess_gmail;

// `gmail_response` is anything that serializes to the Gmail
// `users.messages.get` JSON shape (format=full).
let msg_json = serde_json::to_string(&gmail_response)?;

let parsed  = preprocess_gmail(&msg_json)?;
let context = parsed.to_llm_context();
```

It accepts either the bare `Schema$Message` or a googleapis-style `{"data": ...}` wrapper.

<Tip>
  Any raw RFC 5322 message works in place of a `.eml` file, including bytes fetched over IMAP, from the Gmail API or from any other email source.
</Tip>
